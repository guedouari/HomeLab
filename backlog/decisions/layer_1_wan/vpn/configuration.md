# WireGuard — Configuration

## Environment variables

| Variable | Example | Description |
|----------|---------|-------------|
| `SERVERURL` | `vpn.homelab.example.com` | Public hostname or IP clients use to connect. Use your dynDNS hostname at Layer 2. |
| `SERVERPORT` | `51820` | UDP port exposed to the internet |
| `PEERS` | `phone,laptop,tablet` | Comma-separated peer names (or a count like `3`). Configs auto-generated on first start. |
| `PEERDNS` | `192.168.1.10` | DNS server pushed to peers. Point at AdGuard Home so VPN clients get filtering + split-horizon. |
| `INTERNAL_SUBNET` | `10.13.13.0` | VPN subnet. Clients get addresses starting at `.2`. |
| `ALLOWEDIPS` | `0.0.0.0/0` | Routes pushed to peers. `0.0.0.0/0` = full tunnel (all traffic via VPN). Use `192.168.1.0/24,10.13.13.0/24` for split-tunnel (LAN access only). |
| `LOG_CONFS` | `true` | Print peer QR codes to container logs on first start |
| `PUID` / `PGID` | `1000` | File ownership for generated configs |

## Generated file layout (inside `/config`)

```
/config/
  wg_confs/
    wg0.conf            ← server config (Interface + all Peers)
  server/
    privatekey-server   ← server private key
    publickey-server    ← server public key
  peer_phone/
    peer_phone.conf     ← client config (copy to phone)
    peer_phone.png      ← QR code (scan with WireGuard app)
    privatekey-peer_phone
    publickey-peer_phone
  peer_laptop/
    peer_laptop.conf
    peer_laptop.png
    ...
```

## wg0.conf structure (auto-generated)

```ini
[Interface]
Address    = 10.13.13.1/24
ListenPort = 51820
PrivateKey = <auto-generated>
PostUp     = iptables -A FORWARD -i %i -j ACCEPT; \
             iptables -A FORWARD -o %i -j ACCEPT; \
             iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown   = iptables -D FORWARD -i %i -j ACCEPT; \
             iptables -D FORWARD -o %i -j ACCEPT; \
             iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE

[Peer]
# peer_phone
PublicKey  = <auto-generated>
AllowedIPs = 10.13.13.2/32

[Peer]
# peer_laptop
PublicKey  = <auto-generated>
AllowedIPs = 10.13.13.3/32
```

After initial generation the file is stable and can be edited manually (e.g., to set `PersistentKeepalive` for peers behind NAT).

## Split-tunnel vs full-tunnel

| Mode | `ALLOWEDIPS` | Effect |
|------|-------------|--------|
| Full tunnel | `0.0.0.0/0` | All peer traffic routed through server (blocks ads globally for remote clients) |
| Split tunnel | `192.168.1.0/24,10.13.13.0/24` | Only LAN + VPN traffic via server; internet goes direct |

Split tunnel is lighter on the server and recommended for general LAN access use.

## Router port-forward required

Forward UDP port `51820` (or `SERVERPORT`) on the home router to the server's LAN IP. WireGuard does not need TCP.

## AdGuard Home: no extra config for VPN clients

AdGuard Home binds to the server's LAN IP. VPN clients reach it at that same IP (via the VPN tunnel routing). Set `PEERDNS` to the server's LAN IP and VPN clients automatically use AdGuard Home — no separate AdGuard config needed.
